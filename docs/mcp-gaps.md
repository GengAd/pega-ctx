# What the Pega MCP lacks

Plugin `pega-infinity-authoring` 0.1.7, Infinity 26.1. What made the Pega MCP hard to use as a client, seen while building pega-ctx. One entry per gap: what was seen and where, what pega-ctx does instead, what would fix it on the Pega side. The details are in `docs/mcp-tools.md`; this file is the list to hand back to Pega.

## Writing rules

1. **Only 37 rule classes can be written.** `create-rule` accepts the classes that have a JSON Schema in the plugin and refuses every other one before Pega: `rule type 'Rule-HTML-Section' is not supported by create-rule. Supported types: […] Add schema and builder support for this rule type` (2026-10-11). The list it prints holds no section, declare expression, declare trigger, declare on change, map value, decision tree, message, function, paragraph, access when, access role, REST service, harness or application rule. `update-rule` and `copy-rule` refuse the same classes (server code, plugin 0.1.7). pega-ctx reads and mirrors these types; `create --draft` and `update --draft` write what a developer does in Dev Studio, never sent. *Ask*: a schema for each of these types, Section first, since every UI Kit application is built from sections.
2. **No way to validate without writing.** The schema check only runs inside `create-rule` and `update-rule`, which need a branch and write when the content is valid. pega-ctx validates locally against the plugin's schema files (`pega-ctx lint`). *Ask*: a `validate-rule` tool, or a `dryRun` parameter on the write tools.
3. **The schemas are not served by any tool.** They sit in the plugin's files (`resources/<version>/skills/rules-*/schema/*.json`); `get-skill rules-rule-obj-when/schema/rule-obj-when` answers `skill … not found`, and `list-skills` lists only the examples and references of a skill (2026-10-11). pega-ctx reads the files from disk, which only works where the plugin is installed. *Ask*: `get-skill rules-<class>/schema`, or a `get-rule-schema` tool.
4. **A rule read cannot be written back as is.** `get-rule` returns numbers and booleans as strings (`"10"`, `"true"`), the schema of `create-rule` wants them typed (`/pyInitialCaseUrgency: string trouvé, integer attendu`). pega-ctx types them from the schema before sending (`fitTypes`), and still retries once on the server's message (`withTypesFixed`). *Ask*: one representation for both directions, or the write tools accepting what the read tool returns.
5. **The schemas refuse real rules.** Of 20 real rules of the fixture, prepared as copies, 3 are refused (2026-10-11): a data page whose report definition source lacks `pyLoadReportDefinition`, `pyReportDefinitionClass`, `pyPassCurrentParamPageForActivity`; a report definition with `pyReportDBType` `AlternateNonReplica`, not in the enum (`Standard`, `Alternate`, `""`); the same report's base64 `pyContent.ValidationMap`, where the schema wants `""`. pega-ctx's lint reports them; nothing else can be done locally. *Ask*: schemas checked against rules Pega itself produces.
6. **The server's own stubs fail its schemas.** Prepared as templates, 32 stubs pass and 4 do not: AITool (breaks one of its `x-pega-condition`), ConnectGenerativeAI (`pyGenAIDef`, `pyGenAIConfig`, `pyDescription` required, absent), TestUnitCase (`pyRuleUnderTest.pyDetails` left empty on purpose), UITheme (the schema requires `pyRuleName` to be the constant `Rule-UI-Theme`, most likely a copy of `pxObjClass`, and requires `pyClassName` without declaring it). `tests/lint.test.mjs` pins this list. *Ask*: every top-level example valid against its schema, checked in Pega's build.
7. **Persistence and content share the `pz` prefix.** `get-rule` returns persistence fields (`pzInsKey`, `pzChecksum`…) that must not be sent back, but some types keep real content in `pz*` fields (Notification `pzRecipients`, AI agent `pzActionTools`, report columns `pzIndexCount`). Only the schema tells them apart: pega-ctx keeps a `pz*` field the schema declares with a type (`declaredPz`). *Ask*: `get-rule` with a `forWrite` detail that returns only the fields a write accepts.
8. **The class must exist before its rules, and the error does not say so.** On a missing class, `create-rule` answers `Branch ruleset not candidate`. pega-ctx's instructions create the class first. *Ask*: a message that names the missing class.
9. **A warning on every successful write.** `create-rule` and `update-rule` return "the completed branch summary was not updated" even when the write succeeds. pega-ctx shows it to the user as it is. *Ask*: a warning only when something is wrong.
10. **Errors in the operator's locale.** Schema errors come in French for a French operator (`string trouvé, integer attendu`): a client has to match every language to act on them. pega-ctx matches French and English. *Ask*: structured errors (JSON Pointer, keyword, expected type) next to the sentence.
11. **A branch can be invisible.** After a branch was deleted then recreated with the same name (MESA1, 2026-10-11), `create-rule` writes to it and `get-rule` reads it by key, but `D_pxListRules`, `list-rules` and `search-rules` return nothing from it, and a rule citing another rule of the branch fails. The branch is in `pyBranchList` of the application rule. No MCP tool adds a branch to an application or tells why it is not listed. *Ask*: a tool that lists the branches of the application and their state.
12. **Still to check**: whether the server refuses the four stubs of entry 6 (Trello card 15, on the real server).

## Reading rules

13. **Listing goes through a data page, one rule class per call.** The only listing with update dates is `run-data-page` on `D_pxListRules`. It takes one rule class per call (a list or the `Rule-` prefix gives an error 500), with no filter on date or ruleset. pega-ctx makes one call per type (about forty) and compares dates itself. *Ask*: a `list-rules` with several classes, `updatedSince` and `ruleSet` filters, and dates in its answer.
14. **Case types are listed without name, ruleset nor date.** For `Rule-Obj-CaseType`, the row has only `pxInsName` in upper case (`CLASS!PYDEFAULT`), no ruleset, no update date. pega-ctx reads every case type again at each sync and takes the name and ruleset from the rule. *Ask*: the same columns as the other classes.
15. **Some classes ignore paging.** For classes outside the application (`Rule-RuleSet-Version`, `Rule-Application`), `D_pxListRules` returns the whole system on every page. pega-ctx does not mirror rulesets and branches, and stops when a page repeats. *Ask*: paging honoured, or the application filter applied.
16. **`list-rules` answers in free text, `search-rules` without dates.** pega-ctx does not use them. *Ask*: the same tabular answer as the data page.
17. **`get-rule` has no date.** Neither `pxUpdateDateTime` nor `pxCreateDateTime` in a full rule; the date comes from the listing. *Ask*: the dates in `get-rule`.
18. **The stack stops at the first level.** `get-application` reads only the operator's applications: no climb through the built-on applications, and nothing says which ruleset is unlocked. pega-ctx writes what it sees in `stack.md` and asks the user for the write ruleset of each class (`write` table, `docs/decisions/0006-write-ruleset-per-class.md`). *Ask*: the whole stack with each ruleset's lock state.
19. **Another application needs an alias.** `applicationNames` toward an application other than the current one gives an error 500; `set-application-alias` must come first, with an alias from `list-available-applications`. *Ask*: `applicationNames` working for any application the operator can open.
20. **Everything comes back as TOON text.** No tool returns `structuredContent`; answers are TOON (a compact JSON-like text) ending with a timing line. pega-ctx carries its own TOON decoder (`src/mcp/toon.mjs`). *Ask*: `structuredContent` in JSON next to the text.
